### Security gaps in today's code

These are real now. This area closes them because the threat model (08b) would otherwise list them as unmitigated.

1. **Keystrokes can reach the wrong window.** `KeyboardSender.SendToWindowAsync` focuses the target only
   `if (gameWindow != IntPtr.Zero && Native.IsWindow(gameWindow))`. Otherwise it types into whatever window is in front,
   and with `SendMode.TypeAndSend` it then presses Enter. `App.OpenCompose` records `GetForegroundWindow()`. When the
   reply box is opened from the tray, that window is the taskbar (`explorer.exe`). When the game closes, or the user
   alt-tabs during a slow `KeystrokeDelayMs`, the reply and its Enter go into a browser, chat client or terminal.
2. **Typed text is not sanitised.** Translation output and user `phrases.json` text are typed with `KEYEVENTF_UNICODE`
   or pasted with Ctrl+V. A `\n` from a provider response or a shared phrase file ends the chat line early. The rest of
   the text then arrives with the chat box closed, where letters act as game hotkeys. Bidi overrides (U+202E) make the
   message read differently to other players.
3. **`App.OpenUrl` launches anything.** It is called with `UpdateInfo.PageUrl`, which comes straight from the GitHub
   API's `html_url`. A spoofed response with `file:///…/x.exe` or `\\host\share\x.exe` would run. `UpdateChecker.Parse`
   accepts any `html_url` and any `browser_download_url`.
4. **`phrases.json` is unbounded** in file size, phrase count and text length.
5. **Culture bugs.** `TranscriptWriter.Format` uses `ToString("HH:mm:ss")` under the current culture, where `:` is the
   culture's time separator. `Hotkey.ToString()` uses culture-sensitive `int.ToString()`.

### 3. Security types

Core types live in `src/Envoy.Core/Security/` (namespace `Envoy.Core.Security`). They are static, pure and thread-safe.
User-facing sentences live in `SecurityText` (contract §8.7).

#### 3.1 `OutgoingText.cs`

```csharp
public static class OutgoingText
{
    public const int HardMaxLength = 1000;
    /// Removes C0/C1 controls (CR, LF, TAB → space), removes U+202A–U+202E and U+2066–U+2069, collapses whitespace
    /// runs to one space, trims, truncates to maxLength UTF-16 units without splitting a surrogate pair.
    /// ZWJ/ZWNJ are kept (emoji, Indic scripts). Null → "". Idempotent.
    public static string Sanitize(string? text, int maxLength = HardMaxLength);
    public static bool IsUnsafe(char c);
}
```

The 1000 cap is a safety ceiling against runaway provider output. It is not a claim about any game's chat limit.
Callers:

- `ComposeWindow.SendAsync`: `text = OutgoingText.Sanitize(AppendOriginal(text));` before both the clipboard and
  the typing branches.
- `ComposeWindow`'s copy (Ctrl+Enter) path does the same.
- `KeyboardSender.SendToWindowAsync` sanitises again on entry. This is defence in depth, and safe because `Sanitize`
  is idempotent.

#### 3.2 `SendTargetGuard.cs`, `SecurityText.cs` and the App changes

```csharp
public enum SendTargetVerdict { Ok, NoTarget, TargetClosed, FocusLost }

public static class SendTargetGuard
{
    /// Chooses the window the reply box will type into, at the moment it opens (contract §8.8).
    /// gameWindow != 0 && gameWindowExists → gameWindow. Otherwise foregroundWindow, unless it is 0, its process id
    /// is 0 or ownProcessId, or IsShellProcess(foregroundProcessName) → 0 (no target).
    public static nint ChooseTarget(nint gameWindow, bool gameWindowExists, nint foregroundWindow,
                                    uint foregroundProcessId, string? foregroundProcessName, uint ownProcessId);

    /// "explorer" or "explorer.exe", ordinal ignoring case. explorer.exe owns Shell_TrayWnd and the desktop.
    public static bool IsShellProcess(string? processName);

    /// targetProcessId 0 = unknown → NoTarget. Compared by process, not HWND, so a game that recreates its
    /// top-level window (fullscreen toggle) still matches.
    public static SendTargetVerdict Check(bool hasTarget, bool targetExists, uint targetProcessId, uint foregroundProcessId);
}

public static class SecurityText
{
    public static string SendBlocked(SendTargetVerdict verdict);   // "" for Ok
}
```

`SecurityText.SendBlocked` uses the contract's voice (what happened, then what to do):

- NoTarget: "Nothing was typed because Envoy didn't know which window to type into. Open the reply box over the game
  with your hotkey."
- TargetClosed: "Nothing was typed because the window you were replying to has closed."
- FocusLost: "Envoy stopped typing because another window came to the front. Click back into the game and send again."

**App, `src/Envoy.App/Services/KeyboardSender.cs`.**

```csharp
public sealed class SendBlockedException(SendTargetVerdict verdict)
    : InvalidOperationException(SecurityText.SendBlocked(verdict))
{
    public SendTargetVerdict Verdict { get; } = verdict;
}

/// Called by App.OpenCompose. No new P/Invoke: GetForegroundWindow, GetWindowThreadProcessId and IsWindow exist.
public static IntPtr ResolveTarget(IntPtr gameWindow)
{
    var fg = Native.GetForegroundWindow();
    Native.GetWindowThreadProcessId(fg, out var fgPid);
    return SendTargetGuard.ChooseTarget(gameWindow, gameWindow != IntPtr.Zero && Native.IsWindow(gameWindow),
        fg, fgPid, ProcessNameOf(fgPid), (uint)Environment.ProcessId);
}
// ProcessNameOf: Process.GetProcessById(pid).ProcessName in try/catch → null on failure (reads the process list only).

public static async Task SendToWindowAsync(IntPtr target, string text, ComposeSettings settings, CancellationToken ct = default)
{
    text = OutgoingText.Sanitize(text);
    if (text.Length == 0) return;
    var targetPid = ProcessOf(target);               // 0 when target is Zero or the lookup fails
    Ensure(target, targetPid);                       // NoTarget / TargetClosed before focusing
    Native.SetForegroundWindow(target);
    await Task.Delay(settings.FocusDelayMs, ct);
    Ensure(target, targetPid);                       // FocusLost if focusing failed
    // open-chat key → Ensure → each char: Ensure + SendUnicode | Paste: Ensure + Ctrl+V → Ensure + Enter
}
```

**`App.OpenCompose`** becomes `_compose.Open(KeyboardSender.ResolveTarget(Host.Game?.MainWindow ?? IntPtr.Zero));`.
`ComposeWindow`'s existing `catch` already copies the text to the clipboard and shows `ex.Message`, so it now shows
the `SecurityText` sentence. 02 later turns that box into a problem toast with the same text.

**Behaviour change (CHANGELOG):** a reply opened from the tray or the settings window while no game is detected now

`LoadWithUserFile` works in four steps:

1. When `new FileInfo(userFile).Length > MaxFileBytes`, it returns the built-ins. This is the same path as a JSON
   error, which is silent today. 07's `out error` overload reports both.
2. It deserialises with the cached static options (the CA1869 fix).

4. It merges with the built-ins as today.

Built-in phrases are trusted and are not cleaned.

## Risks & open questions

1. **Windows-only warnings.** The real WPF build might emit warnings the typecheck can't see (markup compiler, WinRT
   projections). `Envoy.App` therefore keeps warnings non-fatal on Windows. **Open:** once 08b's REQ-QSC-7 summary
   shows zero for a release cycle, flip the app to strict.
2. **01 adds code after the baseline.** The re-measurement on the 01 merge commit may find more than the table lists.
   Those findings are fixed with the same rules, never suppressed in bulk. If one cannot be fixed cleanly, it gets a
   `[SuppressMessage]` with a justification and is listed under Deviations.
3. **BannedApiAnalyzers overload coverage.** Each `Process.Start` overload is listed explicitly, and the
   `ProcessStartInfo` type is banned. The `process-launch` text rule is the backstop for any overload the doc-id list
   misses.
4. **`native-denied` in comments.** A contributor writing "we never call OpenProcess" trips the rule. This is
   deliberate, and the message explains why.
5. **Send guard false positives.** A game whose render window belongs to another process (an anti-cheat or launcher
   overlay, for example) would make every send fall back to the clipboard. That failure mode is safe. M-QSC-1 runs on
   each supported title in 08b's compatibility pass. If one title fails, the fix is a per-game list of extra trusted
   process names, never dropping the guard.
6. **`ProcessNameOf` on protected processes** may fail and return `null`. Then the foreground window counts as an
   ordinary target. This only matters with no game detected, and `Check` still requires the foreground process to
   stay the same.
7. **Members with no caller yet.** `RestartSelf` and `RevealFile` land without callers, because contract §5 assigns
   them to this step. This is the one sanctioned exception to "no placeholder members"; 02 is the first caller.
8. **Launcher path.** The contract and this spec use `src/Envoy.App/Security/ShellLauncher.cs`, and the policy
   `launcher` key enforces it. 02 and 06 were corrected in the final consistency pass to name the same path.
